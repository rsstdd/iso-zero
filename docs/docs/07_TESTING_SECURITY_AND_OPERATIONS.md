# Testing, security, performance, and operations

## 1. Quality model

The test strategy follows risk rather than file count. The most heavily tested behaviors are those whose failure would invalidate the architecture:

- Asset privacy and metadata integrity.
- Content and route uniqueness.
- Viewer accessibility and loading behavior.
- Performance budgets.
- Payment idempotency and inventory correctness.

One smoke test is insufficient.

## 2. Local verification command

`pnpm verify` must run the complete non-destructive quality suite required before merge:

```text
format:check
lint
typecheck
unit
content:check
assets:check
build
browser
accessibility
links
structured-data
budgets
```

Commands may run in parallel where outputs do not conflict.

## 3. Unit tests

Required coverage:

- EXIF formatting.
- Exposure-time conversion.
- Currency formatting.
- Schema refinements.
- Route generation.
- Neighbor calculation.
- Dialog state transitions.
- Order state machine.
- Inventory reservation arithmetic.
- Cache-key construction.
- Security-header generation.

Tests must cover missing optional EXIF fields and extreme valid values.

## 4. Integration tests

### Content and manifest

- Generator is idempotent.
- `--check` detects drift and writes nothing.
- Missing original fails with a specific error.
- Duplicate photo ID, gallery slug, and SKU fail.
- Invalid hero reference fails.
- Print route exists for every active complete print and for no other photograph.

### Asset integrity

- Long edge does not exceed 2048 px.
- Width and height match the manifest.
- Color space is sRGB.
- GPS fields are absent.
- Creator and copyright metadata are present where required and supported.
- Derivative hash matches the file.
- Original files are absent from `dist`.

### Commerce

- Session creation ignores client-supplied price.
- Webhook signature failure returns an error without state mutation.
- Repeated event IDs are idempotent.
- Out-of-order events do not cause invalid transitions.
- Concurrent purchase attempts cannot oversell.
- Reservation expiry restores availability.

## 5. Browser tests

Run Playwright against Chromium, Firefox, and WebKit.

### Gallery

- Grid renders with correct count and aspect ratios.
- No horizontal overflow at declared viewport widths.
- Base route content works when JavaScript is disabled.
- Thumbnail fallback opens the bounded derivative.

### Viewer

- Open by keyboard and pointer.
- Correct image, alt, caption, and EXIF populate.
- Escape closes.
- Close button closes.
- Previous and next work.
- Arrow keys work.
- Boundary controls disable correctly.
- Focus returns to the invoking thumbnail.
- Background remains non-interactive while modal.
- Large derivative is not requested before open.
- Only the declared preload policy requests adjacent images.

### Product and checkout

- Correct price, edition, dimensions, and disclosures render.
- Purchase action creates a server session from SKU.
- Client cannot alter price by editing the request.
- Checkout redirect is valid in test mode.

## 6. Accessibility tests

Automated scans cover:

- Homepage.
- Gallery.
- Gallery with dialog open.
- Product page.
- Colophon.
- Legal pages.
- Order confirmation.

Manual test results are recorded by release. Accessibility defects block release when they prevent content access, keyboard operation, focus visibility, or accurate screen-reader output.

## 7. Performance budgets

### Route budgets

| Resource | Gallery budget |
|---|---:|
| JavaScript | ≤3 KB Brotli |
| CSS | ≤20 KB Brotli |
| Initial HTML | ≤60 KB Brotli for a twelve-photo gallery |
| Initial image transfer | Determined per viewport; no 2048 px viewer asset before open |
| DOM nodes | ≤1,500 for the initial gallery |

Budgets scale only through an ADR supported by measurements.

### User-experience thresholds

At the 75th percentile when field data is available:

- LCP ≤2.5 seconds.
- INP ≤200 ms.
- CLS ≤0.1.

Laboratory CI uses stricter repeatable thresholds where practical and tracks trends rather than relying on a single score.

### Build budgets

Record:

- Cold build duration.
- Warm build duration.
- Number of transformed images.
- Derivative cache hit rate.
- Total generated bytes.
- Route count.

A regression exceeding 20% requires investigation or an explicit acceptance note.

## 8. Security controls

### Headers

Deploy at minimum:

- `Content-Security-Policy` appropriate to the actual host, image CDN, and checkout redirect.
- `Strict-Transport-Security` after HTTPS-only deployment is verified.
- `X-Content-Type-Options: nosniff`.
- `Referrer-Policy` selected to balance analytics, privacy, and checkout requirements.
- `Permissions-Policy` disabling unused powerful features.
- Framing controls through CSP `frame-ancestors`.

Do not copy a header set without testing the viewer, fonts, images, analytics, and checkout.

### Supply chain

- Lock pnpm and Node versions.
- Commit the lockfile.
- Run dependency review and vulnerability scanning.
- Use automated update PRs.
- Minimize runtime dependencies.
- Pin CI actions by immutable version or commit according to repository policy.
- Generate an SBOM for releases if the deployment platform supports it without excessive complexity.

### Secrets

- No secrets in static environment variables exposed to client code.
- Separate test and production payment keys.
- Rotate webhook secrets after exposure.
- Restrict object-storage credentials to required read paths.
- Use short-lived CI credentials where supported.

## 9. Image delivery and reuse controls

Controls are described precisely:

| Control | Purpose | Limitation |
|---|---|---|
| 2048 px maximum | Limits delivered resolution | Does not prevent copying |
| Private originals | Prevents accidental source disclosure | Requires storage and access controls |
| GPS removal | Protects location privacy | Does not remove intentionally authored location text |
| IPTC authorship | Preserves attribution | Metadata can be stripped by third parties |
| Hotlink controls | Reduces casual bandwidth theft | Referer can be absent or spoofed; direct access may remain necessary |
| Crawler directives | Express indexing policy | Not access control |
| No unsold photo HTML route | Reduces convenient page-level linking | Asset URLs remain addressable |

No right-click suppression or drag-blocking script is permitted. Those controls are bypassed easily and degrade expected browser behavior.

## 10. Observability

### Static site

Collect only what supports a defined decision. Prefer privacy-preserving aggregate analytics or no analytics until a use case exists.

Useful signals:

- Core Web Vitals.
- Error rate for viewer initialization.
- Broken image requests.
- Checkout-session creation failures.
- Conversion from product page to checkout completion.

### Commerce service

Structured logs include:

- Request ID.
- Public order ID.
- Provider event ID.
- Event type.
- Previous and resulting order state.
- Duration.
- Error code.

Do not log full addresses, payment details, secrets, or raw webhook payloads by default.

### Alerts

Alert on:

- Sustained checkout-session failure.
- Webhook signature failures above a small threshold.
- Unprocessed paid orders.
- Inventory invariant violations.
- Deployment verification failure.

## 11. Release process

1. Merge only after `pnpm verify` passes.
2. Build a preview deployment.
3. Run preview smoke, accessibility, and metadata checks.
4. Record route budgets and build identity.
5. Deploy production.
6. Run post-deploy checks from the public origin.
7. Verify security headers, hotlink policy, robots policy, structured data, and checkout test mode or controlled live transaction.
8. Attach the evidence summary to the release.

Rollback must restore the previous static deployment and preserve transaction-service data integrity.
